1. How to approach an exam TP

In this kind of TP, the statement normally gives you the library, the header to include, the functions available and the function prototype you must implement. You are not expected to invent a parser library. Your job is to connect the provided API to the requested result.

  1. Read the prototype. Identify the inputs, output parameters and return convention. For example, int json_library_total_students(const char *filename) returns a count, while a function receiving struct student *out fills a structure supplied by the caller.
  2. Inspect the data. Open the fixture file. Draw its structure: object, array, key/value pairs, records, sections or nodes.
  3. Find the correct API function. Use the library cheat sheet in this guide. Do not manually split JSON/YAML/quoted CSV in a library exercise.
  4. Parse once. A normal library exercise follows: open/read input → parse → navigate nodes → check types → perform the requested operation.
  5. Use a loop for collections. An array/list/sequence normally means loop over its elements and process each record.
  6. Handle failure paths. Check file opening, parse return value, node existence, type and output writing.
  7. Release resources. Close files, delete parser trees/documents and free allocated strings.
  8. Test a small case. Run make, then ./exo. Also test missing keys, empty arrays and unknown IDs where relevant.
Do not start by writing all the code. First write down the sequence of operations in plain language. Then translate each operation to one C statement or library call.

Why use a temporary file for update/delete?

For a small text file, the simplest safe pattern is:

  1. Open the original file for reading.
  2. Open temporary.txt for writing.
  3. Read each record. Write the original record or its modified version to the temporary file.
  4. Close both files and check errors.
  5. Replace the original with the temporary file using remove/rename (check their return values).

This avoids trying to insert or remove bytes in the middle of a text file. In a more robust program, also protect against a failed rename and keep a backup.

3. Fundamentals — CSV parsed manually

Folder: fundamentals/csv_manualStandard C only

The fixture is simple: one header line, then id,name,grade. This exercise deliberately excludes quoted fields; the quoted-field problem is in the libcsv exercise.

id,name,grade
1,Ada,18
2,Bob,14
3,Chihiro,17

Useful functions

fopenfgetsstrchrstrtok (only in this simple subset)strcmpstrtolfprintffcloseremoverename

csv_count_rows(filename) — count data rows

Plan: open file in read mode; read the first line as the header; then count each successfully read line; close the file; return the number. Return -1 if the file cannot be opened.

Important: do not count the header. Decide how blank lines should be treated. For this fixture, count non-empty data lines.

csv_find_student(filename, id, out, out_size) — find one student

  1. Open the file and skip the header.
  2. For every line, split the simple line into three fields: ID, name and grade.
  3. Convert the first field to an integer using strtol.
  4. If the ID equals the requested ID, copy the name into out. Check that the destination buffer is large enough and terminate the string with '\\0'.
  5. Close the file and return 0. If no matching ID exists, return -1.

Note: strtok is acceptable only because this Fundamentals fixture promises that fields are not quoted and names do not contain commas. It is not a correct general CSV parser.

csv_add_student(filename, id, name, grade) — append a record

Open with mode "a", which appends at the end. Write one line using fprintf(fp, "%d,%s,%d\\n", ...). Check fprintf and fclose errors. In a real CSV writer, a name containing a comma or quote must be escaped/quoted; this simple exercise excludes that case.

csv_update_grade(filename, id, grade) — update one field

  1. Read the original line by line.
  2. Write the header unchanged to a temporary file.
  3. For each data row, parse its ID. If it matches, write the same ID and name with the new grade. Otherwise copy the original line.
  4. Track whether you found the ID. If not found, return -1 and do not replace the original.
  5. Close both files, then replace the original with the temporary file.

Do not overwrite the original while you are still reading it.

csv_delete_student(filename, id) — remove one record

Use the same temporary-file method as update, but simply do not write the matching record. Copy every other line. Track whether the ID was found. If it was not found, report failure and preserve the original.

4. Fundamentals — INI

Folder: fundamentals/ini_manual INI is line based. A section is written between brackets; key/value pairs are written as key=value.

[server]
host=localhost
port=8080

[display]
theme=dark

Useful functions

fgetsstrchrstrcmpisspacestrlenfprintf

Write a small helper of your own such as trim(char *s). It removes spaces, tabs and the newline at the beginning/end of a line. Use isspace((unsigned char)c); the cast avoids undefined behaviour for negative signed-char values.

ini_get(filename, section, key, out, out_size)

  1. Read each line with fgets and trim it.
  2. Ignore empty lines and lines whose first non-space character is # or ;.
  3. If a line begins with [ and has a closing ], extract its section name and update a variable such as inside_section.
  4. Only while inside_section is true, find = using strchr.
  5. Trim the left and right parts. Compare the left part with the requested key using strcmp.
  6. Copy the right part into out after checking out_size. Return 0 if found, otherwise -1.

Why track the section? Because two different sections can contain the same key name.

ini_set(filename, section, key, value)

Rewrite into a temporary file. Track the active section. When the requested section is reached, either replace the matching key line with key=value or copy it. If the key did not exist but the section did, insert the new key before leaving the section. If the section did not exist, append a blank line, a new [section] and the key/value line. Use flags such as section_found and key_written so you do not append duplicates.

ini_delete(filename, section, key)

Use the same line-by-line scan. Do not copy the matching key line while you are inside the requested section. Copy everything else. If the key is not found, report failure according to the prototype's convention.

5. Fundamentals — JSON parsed manually (restricted subset)

Folder: fundamentals/json_manualNo JSON library in this exercise

{
  "course": "Structured Data",
  "year": 2026,
  "semester": 1,
  "students": [
    {"id": 1, "name": "Ada"},
    {"id": 2, "name": "Bob"},
    {"id": 3, "name": "Chihiro"}
  ]
}
Important: this manual JSON exercise supports only the small subset described in its README: top-level strings, non-negative integers, and a top-level students array containing simple objects. It is not a complete JSON parser. Do not use this approach for arbitrary production JSON.

Why JSON needs more care

A JSON object uses braces, arrays use brackets, keys and strings use quotes, and commas/colons separate values. Whitespace can appear anywhere between tokens. A word such as "year" might occur inside another string, so searching the whole file with strstr is not enough. You must know whether the parser is at the top-level object, inside an array, or inside a string.

Small scanner helpers to write

HelperResponsibility
skip_ws(const char **p)Move the cursor past spaces, tabs, CR and LF.
parse_string(const char **p, char *out, size_t cap)Expect an opening quote, copy characters until the closing quote, and advance the cursor. In this exercise's limited subset, strings do not require full Unicode escape support.
parse_uint(const char **p, int *out)Read digits and convert them to a non-negative integer. Reject an empty number and overflow.
skip_value(const char **p)Skip one supported value while respecting strings, objects and arrays. This is needed when a key is not the one you are searching for.

These are your own helper functions, not predefined C functions. The standard library functions that help are isspace, isdigit, strtol, strlen, memcpy and fread.

json_get_string(filename, key, out, out_size)

  1. Read the complete file into a null-terminated buffer.
  2. Set a cursor to the first non-whitespace character and expect {.
  3. At the top object level, parse a key string, expect :, then inspect the value's first character.
  4. If the key matches, require that its value begins with a quote, parse the string and copy it to out.
  5. If it does not match, call your skip_value helper and continue after the comma.
  6. Return -1 if the key is missing, has the wrong type, the file is malformed or the output buffer is too small.

json_get_int(filename, key, out)

Follow the same top-level object scan. When the key matches, require a digit and parse the integer with your scanner or strtol. Check the end pointer and range. If the matching key has a string or array instead of a number, return -1.

json_count_students(filename)

  1. Scan the root object until the top-level key students is found.
  2. Require [ after the colon.
  3. Read array elements one by one. In this fixture each element is an object, so require {, parse/skip its fields until its matching }, then increment the count.
  4. Stop at the array's closing ]. Check commas and closing delimiters.

Count objects, not commas: commas also separate properties inside each student object.

json_update_semester(filename, semester)

Find the top-level semester key using the same scanner. Record the start and end positions of its integer token. Build a new text buffer containing: original text before the value + the new integer text + original text after the value. Write that buffer to a temporary file, then replace the original only if all writes succeed. This preserves the rest of the JSON formatting and fields.

Exam tip: when the exercise says “manual parsing”, no call like cJSON_Parse should appear. When the exercise says “use cJSON”, do not recreate the JSON parser with strstr or manual brace counting.

6. Fundamentals — YAML parsed manually (restricted subset)

Folder: fundamentals/yaml_manual

course: Structured Data
room: B204
modules:
  - CSV
  - JSON
  - YAML

This version supports top-level scalar lines such as room: B204 and a simple list under modules. It does not support the full YAML language.

Useful functions

fgetsstrchrstrcmpisspacefprintf

yaml_get(filename, key, out, out_size)

  1. Read one line at a time and trim the newline.
  2. Ignore blank lines and comments beginning with #.
  3. Find the first :. The left side is the key; the right side is the value.
  4. Trim both parts. Compare the key with the requested key.
  5. Copy the scalar value if it fits in the output buffer. Return -1 when missing.

For this subset, the target scalar is at the top level; do not treat an indented list entry as a top-level property.

yaml_count_modules(filename)

Track when you have read the exact modules: line. After that, count lines whose trimmed content begins with -. Stop when a new non-indented top-level key begins. Ignore comments and blank lines.

yaml_set(filename, key, value)

Rewrite through a temporary file. Replace the matching top-level key: old_value line with key: new_value. If no key exists, append the new top-level line. Do not accidentally insert it inside the modules list.

7. Fundamentals — TOML parsed manually (restricted subset)

Folder: fundamentals/toml_manual

[database]
host = "127.0.0.1"
port = 5432

[app]
name = "Cat Bureau"

TOML sections are called tables and are written as [table_name]. Key/value lines belong to the most recently seen table.

Useful functions

fgetsstrchrstrcmpisspacestrtolfprintf

toml_get(filename, table, key, out, out_size)

  1. Read and trim each line.
  2. If the line begins with [, extract the table name and update a boolean indicating whether the requested table is active.
  3. Inside the requested table, find =.
  4. Trim the key and value. Compare the key.
  5. For this exercise, the target value is a quoted basic string: remove its surrounding quotes and copy it to out.

toml_update_int(filename, table, key, value)

Use the same table-tracking scan. In the requested table, find the key line and replace only its integer value with the new integer. Write all lines to a temporary file. Do not change a similarly named key in another table.

The exercise excludes arrays, dates, inline tables and multiline strings. A real TOML parser must handle those features; this is intentionally a small manual exercise.

Folder: fundamentals/xml_manual

<?xml version="1.0"?>
<course>
  <title>Structured Data</title>
  <student><name>Ada</name></student>
  <student><name>Bob</name></student>
</course>

Useful functions

fopenfreadstrstrstrlenmemcpyfprintf

xml_get_text(filename, name, out, out_size)

  1. Read the document into a null-terminated string.
  2. Build/search for the opening tag <name> and locate the matching closing tag </name>.
  3. The text between them is the requested content. Check its length against out_size, copy it and append '\\0'.
  4. Return -1 if the file or either tag is missing.

This is only valid for the exercise's simple non-nested target elements. A full XML parser must handle attributes, entities, namespaces, CDATA, comments and nesting.

xml_count_students(filename)

Repeatedly search for the exact opening tag <student>, increment a counter and advance the search pointer. Do not count the closing tag </student>.

xml_set_text(filename, name, value)

Find the opening and closing tags, then rebuild the text as prefix + new value + suffix. Write the rebuilt document to a temporary file and replace the original only after successful writes.

9. Fundamentals — SQL using SQLite's C API

Folder: fundamentals/sql_manualHeader: sqlite3.hLink: -lsqlite3

SQL is a query language. SQLite stores its database in school.db. First create the database from the supplied script:

cd fundamentals/sql_manual
sqlite3 school.db < school.sql
make
./exo

The seven SQLite calls to recognize

FunctionPurpose
sqlite3_open(filename, &db)Open/create a database and give you a connection pointer.
sqlite3_prepare_v2(db, sql, -1, &stmt, NULL)Prepare SQL into a statement object. Use ? placeholders for values.
sqlite3_bind_int(stmt, index, value)Put an integer into a placeholder. Placeholder indexes start at 1.
sqlite3_bind_text(stmt, index, text, -1, SQLITE_TRANSIENT)Put text into a placeholder; SQLITE_TRANSIENT asks SQLite to copy it.
sqlite3_step(stmt)Run/advance the statement. SELECT returns SQLITE_ROW for a row; completion is SQLITE_DONE.
sqlite3_column_int(stmt, col)Read an integer from the current SELECT row. Column indexes start at 0.
sqlite3_finalize(stmt), sqlite3_close(db)Release the statement and then the database connection.
A prepared statement is like a reusable, compiled SQL command. The SQL text contains ? placeholders; you bind actual values separately. This avoids unsafe string concatenation.

sql_count_students(filename)

Open DB → prepare SELECT COUNT(*) FROM students; → call sqlite3_step once and expect SQLITE_ROW → read column 0 with sqlite3_column_int → finalize → close → return count.

sql_add_student(filename, id, name, grade)

Prepare INSERT INTO students(id, name, grade) VALUES (?, ?, ?);. Bind ID at index 1, name at index 2 and grade at index 3. Call sqlite3_step and expect SQLITE_DONE. Finalize and close.

sql_update_grade(filename, id, grade)

Prepare UPDATE students SET grade = ? WHERE id = ?;. Bind new grade at 1 and ID at 2. Execute. You can use sqlite3_changes(db) before closing to know whether a row changed.

sql_delete_student(filename, id)

Prepare DELETE FROM students WHERE id = ?;, bind the ID, execute to SQLITE_DONE, finalize and close.

/* The essential prepared-statement pattern */
sqlite3 *db = NULL;
sqlite3_stmt *stmt = NULL;

if (sqlite3_open(filename, &db) != SQLITE_OK)
    return -1;
if (sqlite3_prepare_v2(db,
        "SELECT COUNT(*) FROM students;", -1, &stmt, NULL) != SQLITE_OK) {
    sqlite3_close(db);
    return -1;
}
if (sqlite3_step(stmt) != SQLITE_ROW) {
    sqlite3_finalize(stmt);
    sqlite3_close(db);
    return -1;
}
int count = sqlite3_column_int(stmt, 0);
sqlite3_finalize(stmt);
sqlite3_close(db);
return count;

10. Proficiencies — CSV using libcsv

Folder: proficiencies/csv_libraryHeader: csv.hLink: -lcsv

This fixture includes a comma inside a quoted name and an escaped quote:

id,name,grade
1,"Ada Lovelace",18
2,"Bob, Jr.",14
3,"Chihiro ""Sky""",17
4,"Dora",9

A simple strtok(line, ",") splits the name Bob, Jr. into two pieces. The library understands quoted fields for you.

How libcsv works

  1. csv_init(&parser, options) initializes a parser state.
  2. Read chunks from the file with fread.
  3. Give each chunk to csv_parse.
  4. libcsv calls your field callback when one field is complete, and your row callback when a record ends.
  5. Call csv_fini after the last chunk so the final field/row is processed even if the file has no final newline.
  6. Call csv_free when finished.

Callback signatures

void field_callback(void *field, size_t length, void *user_data);
void row_callback(int terminator, void *user_data);

The callback's user_data is how you pass your own context structure into the callbacks. For example:

struct csv_context {
    char fields[3][128];
    size_t field_count;
    int row_number;
    int valid_records;
    int wanted_id;
    struct student found;
    int found_flag;
};

In field_callback, copy exactly length bytes into the next field slot and append '\\0'. Do not keep the field pointer after the callback returns: libcsv owns/reuses its internal buffer. In row_callback, the three saved fields form one row. Skip row 0 because it is the header; convert ID and grade; update your counters or matching student; then reset field_count to 0 for the next row.

Functions for this exercise

csv_library_count(filename)

Run the parser and increment a record count in the row callback, excluding the header. Return -1 if opening or parsing fails.

csv_library_find(filename, id, out)

Store the requested ID in the callback context. For each data row, convert field 0 to an integer; if it matches, fill out->id, copy field 1 into out->name and convert field 2 into out->grade. Do not return a pointer into the parser buffer.

csv_library_average(filename)

For each valid data row, add the grade to sum and increment count. At the end, return (double)sum / count. Handle the case count == 0 before dividing.

csv_library_filter(input, output, minimum)

For each row with grade >= minimum, write a record to the output CSV. Use csv_fwrite for text fields that may need escaping. It writes one quoted CSV field; you must write commas between fields and the record newline yourself. Open CSV files in binary mode when using libcsv's file APIs.

Important libcsv functions

FunctionMeaning
csv_initInitialize parser.
csv_parseParse a chunk and invoke callbacks.
csv_finiFlush the final field/record.
csv_freeRelease parser buffers.
csv_error, csv_strerrorGet parser error code/message.
csv_fwriteWrite one escaped field to a file.
/* The core parsing loop */
struct csv_parser parser;
char buffer[1024];
size_t n;

if (csv_init(&parser, CSV_STRICT) != 0)
    return -1;
while ((n = fread(buffer, 1, sizeof(buffer), fp)) > 0) {
    if (csv_parse(&parser, buffer, n,
                  field_callback, row_callback, &context) != n) {
        /* csv_error(&parser), csv_strerror(...) */
        csv_free(&parser);
        return -1;
    }
}
csv_fini(&parser, field_callback, row_callback, &context);
csv_free(&parser);

11. Proficiencies — JSON using cJSON

Folder: proficiencies/json_libraryHeader: cJSON.hLink: -lcjson

Fixture structure:

{
  "courses": [
    {
      "id": 10,
      "title": "C Programming",
      "room": "A101",
      "students": [
        {"name": "Ada", "grade": 18},
        {"name": "Bob", "grade": 12}
      ]
    },
    {
      "id": 20,
      "title": "Structured Data",
      "room": "B204",
      "students": [
        {"name": "Chihiro", "grade": 17},
        {"name": "Dora", "grade": 9}
      ]
    }
  ]
}

The basic cJSON workflow

  1. Read the whole file into a string (for example with fopen, fseek, ftell, malloc and fread).
  2. Parse it: cJSON *root = cJSON_Parse(text);.
  3. Find a property with cJSON_GetObjectItemCaseSensitive(object, "key").
  4. Check its type using cJSON_IsObject, cJSON_IsArray, cJSON_IsString or cJSON_IsNumber.
  5. For arrays use cJSON_GetArraySize/cJSON_GetArrayItem or cJSON_ArrayForEach.
  6. Modify/create nodes if needed.
  7. Serialize with cJSON_Print or cJSON_PrintUnformatted.
  8. Write the returned string to a file, then free it and cJSON_Delete(root).

Most useful cJSON functions

FunctionUse
cJSON_Parse(text)Convert JSON text into a cJSON tree. Returns NULL on parse failure.
cJSON_Delete(root)Delete the parsed tree and its owned children.
cJSON_GetObjectItemCaseSensitive(obj, key)Get one object property by exact key spelling.
cJSON_IsObject/IsArray/IsString/IsNumberCheck node type before reading it.
cJSON_GetArraySize(arr)Get number of array elements.
cJSON_GetArrayItem(arr, i)Get an array element by index.
cJSON_ArrayForEach(item, arr)Loop over array/object children.
cJSON_GetStringValue(item)Get string content after confirming it is a string.
cJSON_GetNumberValue(item)Read a number as double after confirming numeric type.
cJSON_SetValuestring(item, text)Change an existing string node.
cJSON_SetNumberValue(item, number)Change an existing number node.
cJSON_CreateArray/Object/String/NumberCreate a JSON array, object, string or number node.
cJSON_AddItemToArray, cJSON_AddItemToObjectAttach a new child to an array or object.

Memory rule: the result of cJSON_Parse must be deleted with cJSON_Delete. The string returned by cJSON_Print is separately allocated and must be freed with free (for the default allocator). Once you add a child node to an object/array, that parent owns it; do not delete the child separately.

json_library_count_courses(filename)

  1. Parse the file.
  2. Get courses from the root object.
  3. Check cJSON_IsArray(courses).
  4. Count it with cJSON_GetArraySize(courses).
  5. Delete root and return the count.

json_library_total_students(filename)

  1. Get and validate the courses array.
  2. For each course object, get its students property.
  3. Check that students is an array.
  4. Add its array size to a total.
  5. Delete root and return the total.

For the supplied fixture the expected total is 4.

json_library_update_room(filename, course_id, room)

  1. Parse root and get the courses array.
  2. Loop over each course object. Read its id property and check that it is a number.
  3. When the ID matches, get room and check that it is a string.
  4. Call cJSON_SetValuestring(room_node, room).
  5. Serialize the entire root with cJSON_Print and write it back to the file (prefer a temporary file).
  6. Free the printed text and delete root.

json_library_export_top(input, output, minimum)

  1. Parse input; navigate root → courses array → each course → students array.
  2. For each student object, read name and grade; check string/number types.
  3. If grade is at least minimum, create a JSON object containing the student's name and grade.
  4. Add that object to a new array with cJSON_AddItemToArray.
  5. Print the new array using cJSON_Print, write it to output, free the printed string, and delete both JSON trees.

12. Very important — JSON → C struct (extract a whole block)

This is likely the part you are asking about. You can extract a complete JSON array/object block into your own C structures, but cJSON does not automatically fill a C struct for you. You first get a pointer to the JSON block, then walk through its fields and copy each value into your struct.

12.1 Understand the two representations

JSON has named properties and arrays:

{
  "courses": [
    { "id": 10, "title": "C Programming", "room": "A101" }
  ]
}

In C, you might represent the same information with:

typedef struct {
    int id;
    char title[64];
    char room[32];
} Course;

typedef struct {
    Course courses[10];
    size_t course_count;
} CourseBlock;

The JSON property courses is an array. The C field courses is an array of Course. Each JSON object inside the array becomes one C Course.

12.2 Navigate to the block first

cJSON *root = cJSON_Parse(json_text);
if (root == NULL)
    return -1;

/* Get the whole "courses" array node */
cJSON *courses_json = cJSON_GetObjectItemCaseSensitive(root, "courses");
if (!cJSON_IsArray(courses_json)) {
    cJSON_Delete(root);
    return -1;
}

/* Get the first object inside the array */
cJSON *first_course = cJSON_GetArrayItem(courses_json, 0);
if (!cJSON_IsObject(first_course)) {
    cJSON_Delete(root);
    return -1;
}

courses_json points to the entire JSON array block. first_course points to one object in that block. These are pointers into the parsed tree; do not call free on them or delete them separately.

12.3 Extract one object into one struct

Course course;
cJSON *id_node = cJSON_GetObjectItemCaseSensitive(first_course, "id");
cJSON *title_node = cJSON_GetObjectItemCaseSensitive(first_course, "title");
cJSON *room_node = cJSON_GetObjectItemCaseSensitive(first_course, "room");

if (!cJSON_IsNumber(id_node) ||
    !cJSON_IsString(title_node) ||
    !cJSON_IsString(room_node)) {
    cJSON_Delete(root);
    return -1;
}

course.id = (int)cJSON_GetNumberValue(id_node);
snprintf(course.title, sizeof(course.title), "%s",
         cJSON_GetStringValue(title_node));
snprintf(course.room, sizeof(course.room), "%s",
         cJSON_GetStringValue(room_node));

Now course is an ordinary C structure. You can pass it to another function, store it in an array or print its fields.

12.4 Extract the whole courses array into a C array (complete example)

This is a full example for the simpler fields id, title and room. It accepts a maximum capacity, so it cannot write past the provided array.

#include <stdio.h>
#include <stddef.h>
#include <string.h>
#include <cjson/cJSON.h>

typedef struct {
    int id;
    char title[64];
    char room[32];
} Course;

int extract_courses(cJSON *root, Course *out,
                    size_t capacity, size_t *count)
{
    cJSON *array;
    cJSON *item;
    size_t used = 0;

    if (root == NULL || out == NULL || count == NULL)
        return -1;

    array = cJSON_GetObjectItemCaseSensitive(root, "courses");
    if (!cJSON_IsArray(array))
        return -1;

    cJSON_ArrayForEach(item, array) {
        cJSON *id_node;
        cJSON *title_node;
        cJSON *room_node;
        const char *title;
        const char *room;

        if (used == capacity)
            return -1;
        if (!cJSON_IsObject(item))
            return -1;

        id_node = cJSON_GetObjectItemCaseSensitive(item, "id");
        title_node = cJSON_GetObjectItemCaseSensitive(item, "title");
        room_node = cJSON_GetObjectItemCaseSensitive(item, "room");

        if (!cJSON_IsNumber(id_node) ||
            !cJSON_IsString(title_node) ||
            !cJSON_IsString(room_node))
            return -1;

        title = cJSON_GetStringValue(title_node);
        room = cJSON_GetStringValue(room_node);
        if (title == NULL || room == NULL)
            return -1;

        out[used].id = (int)cJSON_GetNumberValue(id_node);
        snprintf(out[used].title, sizeof(out[used].title), "%s", title);
        snprintf(out[used].room, sizeof(out[used].room), "%s", room);
        used++;
    }

    *count = used;
    return 0;
}

Usage:

Course courses[10];
size_t course_count = 0;

/* root is the result of cJSON_Parse(...) */
if (extract_courses(root, courses, 10, &course_count) == 0) {
    for (size_t i = 0; i < course_count; i++)
        printf("%d %s %s\\n", courses[i].id,
               courses[i].title, courses[i].room);
}

cJSON_Delete(root);

12.5 Nested JSON blocks: struct inside struct

The supplied JSON has students inside each course. Model that nesting in C:

typedef struct {
    char name[64];
    int grade;
} Student;

typedef struct {
    int id;
    char title[64];
    char room[32];
    Student students[20];
    size_t student_count;
} Course;

Then inside the loop for one course, after reading ID/title/room:

cJSON *students_json = cJSON_GetObjectItemCaseSensitive(item, "students");
if (!cJSON_IsArray(students_json))
    return -1;

out[used].student_count = 0;
cJSON *student_json;
cJSON_ArrayForEach(student_json, students_json) {
    cJSON *name_node;
    cJSON *grade_node;
    size_t s = out[used].student_count;

    if (!cJSON_IsObject(student_json) || s == 20)
        return -1;
    name_node = cJSON_GetObjectItemCaseSensitive(student_json, "name");
    grade_node = cJSON_GetObjectItemCaseSensitive(student_json, "grade");
    if (!cJSON_IsString(name_node) || !cJSON_IsNumber(grade_node))
        return -1;

    snprintf(out[used].students[s].name,
             sizeof(out[used].students[s].name), "%s",
             cJSON_GetStringValue(name_node));
    out[used].students[s].grade =
        (int)cJSON_GetNumberValue(grade_node);
    out[used].student_count++;
}

12.6 The pattern to remember

{ ... } objectcJSON_GetObjectItemCaseSensitivestruct
[ ... ] arraycJSON_IsArray, cJSON_ArrayForEachC array + count
StringcJSON_IsString, cJSON_GetStringValuechar field[N]
NumbercJSON_IsNumber, cJSON_GetNumberValueint or double
Do not do this: memcpy(&my_struct, json_node, sizeof(my_struct)). A cJSON node is not laid out like your struct. You must map every property explicitly. Also, do not keep valuestring pointers after deleting root; copy the text into your struct first.

Fixture:

project: Cat Bureau
tasks:

libyaml does not give you the same simple key lookup API as cJSON. It parses YAML into a document tree. In this exercise, the important node types are:

Node typeMeaningFixture example
YAML_MAPPING_NODEKey/value mapping.project: Cat Bureau, each task mapping.
YAML_SEQUENCE_NODEOrdered list.The tasks list.
YAML_SCALAR_NODEOne text/scalar value.project, done, Parse CSV.

Parsing and getting the document

FILE *fp = fopen(filename, "rb");
yaml_parser_t parser;
yaml_document_t document;

if (fp == NULL)
    return -1;
if (!yaml_parser_initialize(&parser)) {
    fclose(fp);
    return -1;
}
yaml_parser_set_input_file(&parser, fp);
if (!yaml_parser_load(&parser, &document)) {
    yaml_parser_delete(&parser);
    fclose(fp);
    return -1;
}

yaml_node_t *root = yaml_document_get_root_node(&document);
/* Inspect root and child nodes here. */

yaml_document_delete(&document);
yaml_parser_delete(&parser);
fclose(fp);

How to navigate the tree

  1. The root for this fixture should be a mapping.
  2. Loop through root->data.mapping.pairs.
  3. For each pair, get the key node and value node using yaml_document_get_node(&document, pair->key) and ...pair->value.
  4. Check if the key is the scalar text tasks.
  5. Its value should be a sequence. Loop through sequence.items. Each item is a node ID; get the task node with yaml_document_get_node.
  6. Each task should be a mapping. Loop over its pairs to find id or status.
/* Conceptual mapping/sequence traversal */
if (root != NULL && root->type == YAML_MAPPING_NODE) {
    yaml_node_pair_t *pair;
    for (pair = root->data.mapping.pairs.start;
         pair != root->data.mapping.pairs.top; pair++) {
        yaml_node_t *key_node = yaml_document_get_node(&document, pair->key);
        yaml_node_t *value_node = yaml_document_get_node(&document, pair->value);
        /* Compare key_node's scalar value with "tasks". */
        /* If it is "tasks", require value_node->type == YAML_SEQUENCE_NODE. */
    }
}

Functions for the exercise

yaml_library_count_tasks(filename)

Parse the YAML document → find top-level tasks mapping value → check sequence type → the number of sequence items is the task count. Return -1 on parse/type failure.

yaml_library_count_status(filename, status)

Find the tasks sequence. For each task mapping, search its pairs for the status scalar. Compare its scalar bytes and length with the requested status. Increment the count when equal. Remember: compare using the scalar's recorded length; YAML scalar values are not guaranteed to be null-terminated for every API use.

yaml_library_update_status(filename, id, status)

Find the task mapping whose id scalar parses to the requested integer. Rebuild the output document with the same top-level key/value pairs and tasks, replacing the chosen status scalar. libyaml's document-building functions include yaml_document_initialize, yaml_document_add_mapping, yaml_document_add_sequence, yaml_document_add_scalar, yaml_document_append_mapping_pair and yaml_document_append_sequence_item. Emit it using yaml_emitter_initialize, yaml_emitter_set_output_file and yaml_emitter_dump.

Emitter / output functions

FunctionPurpose
yaml_emitter_initializeInitialize the emitter.
yaml_emitter_set_output_fileChoose the output FILE.

libyaml's API is lower-level than cJSON. The most important thing is to identify mapping, sequence and scalar node types, then follow node IDs to navigate. Do not assume YAML is only indentation and colon characters.

15. Common mistakes and final checklist

Common mistakes

  • Using a library without including its header: include the header shown in the subject, e.g. cJSON.h, csv.h or yaml.h.
  • Forgetting the linker flag: #include only makes declarations visible; -lcjson/-lcsv/-lyaml links the library implementation.
  • Not checking a parser result: cJSON_Parse can return NULL; libyaml parser calls can fail; fopen can fail.
  • Reading a value before checking its type: check number/string/array/object first.
  • Using a pointer after freeing its owner: cJSON string pointers belong to the tree. Copy them before cJSON_Delete.
  • Forgetting finalization: call csv_fini after all chunks; finalize SQLite statements; close all files.
  • Counting the header row: CSV fixtures have a first header record.
  • Using strtok on quoted CSV: a comma can be inside a quoted name.
  • Overwriting the input before output is ready: serialize/write to a temporary file first for update/delete operations.
  • Assuming a struct is the same thing as a JSON object: map the fields explicitly, do not memcpy a cJSON node.

Before submitting

  • Does the code compile with -std=c99 -Wall -Wextra -Werror -pedantic?
  • Did you respect the exact function prototype in exercise.h?
  • Did you check file-open and parse failures?
  • Did you verify that every requested JSON/YAML node has the expected type?
  • Did you handle “not found” without returning uninitialized data?
  • Did you close files and release parser/library memory?
  • Did you test a missing ID, wrong type, empty array and parse error when appropriate?
